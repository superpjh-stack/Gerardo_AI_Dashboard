# 저장 구조 v0.1 · 현재 구현

SQLite는 .local/monitor.sqlite3. 원본 로그와 별개이며 Git에서 제외한다.

| 테이블 | 용도 |
|---|---|
| sources | 도구별 연결·수집 상태 JSON |
| files | provider/path 복합키, 파서 버전·inode·크기·mtime 체크포인트 |
| event_instances | 파일별 정규화 이벤트 스냅샷. 같은 이벤트의 복사본을 별도 보존 |
| events | event_id 고유키로 중복 제거한 조회용 이벤트 |
| notes | 세션 ID 해시와 사용자 메모 |
| confirmations | 세션 ID 해시와 사용자 확인 시각 |

세션·프로젝트·사용량·작업은 events에서 파생한다. 첫 버전은 별도 관계형 테이블로 분리하지 않았다.
원본 전문·코드·tool arguments를 저장하지 않는다. 메타데이터, 사용량, 도구 이름, 상대 파일/행 참조만 저장한다.
파일별 이벤트 재구성, 집계 이벤트 갱신, 체크포인트 변경은 하나의 트랜잭션이다.
읽기에 실패한 파일은 이전 정상 데이터를 유지한다. 동기화는 단일 락으로 직렬화한다.
복사·회전된 파일 스냅샷을 유지해 원본 일부가 잘려도 수집된 이력을 잃지 않는다.
지워진 원본의 스냅샷은 자동 삭제하지 않는다. 보존 기간·삭제 UI는 후속 범위다.

## 원격 전용 저장소
private Compose는 공개 demo와 별도 SQLite 볼륨을 사용한다.
`incoming_runs`, `incoming_events`는 검증 전 배치와 완료 영수증을 보관한다(24시간 후 정리).
완료 검증 후 해당 기기의 events/event_instances 스냅샷만 원자 교체한다.
`remote_state`는 마지막 전송의 소스 상태·수신 시각, `auth_sessions`는 세션 토큰 SHA256과 만료,
`login_attempts`는 재시작으로 초기화되지 않는 로그인 실패 제한을 저장한다.
원본 파일 경로·메모·대화·코드·도구 인자는 전송 대상에 포함되지 않는다.
