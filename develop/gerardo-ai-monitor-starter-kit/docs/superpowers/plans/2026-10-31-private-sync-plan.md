# 실제 기록 전송 구현 순서

승인된 설계: ../specs/2026-10-31-private-sync-design.md
실행: 현재 세션에서 순차 구현. writing-plans 스킬은 설치되어 있지 않아 이 문서에 구현·검증 순서를 기록한다.

1. private 모드 접근 보호: 로그인, 만료 세션, 로그아웃, 출처 검증, 로그인 실패 제한. 비밀 설정 누락 시 시작 실패.
2. 허용 필드 전송 스키마, 해시 식별자, 배치 임시 저장과 전체 스냅샷 검증 후 원자적 반영.
3. 수동 전송 스크립트: 지정된 로컬 소스 수집, 페이로드 검증, HTTPS 전송, 개수·해시·집계 확인.
4. 프런트엔드에 VPS 실제 기록·최종 수신 상태·로그아웃 표시. 서버에서 로컬 스캔 금지.
5. 테스트: 비인증·권한 분리·CSRF·만료·중복·불완전 전송·원문/경로 필드 거부·로컬/데모 회귀.
6. 별도 Compose 서비스와 Caddy HTTPS 배포. 443은 유지, 사용 중이지 않은 80(인증서 검증)과 18790(HTTPS) 사용.
7. 기존 SSH 인증으로 비밀 설정 전달. 로컬 비공개 파일에 접속 정보 보관. Git/출력에 비밀값을 넣지 않는다.
8. 외부 HTTPS·접근 보호 검증 후 실제 메타데이터 최초 전송 및 로컬 집계 대조. 결과 문서와 GitHub 반영.

공개 체험판과 실제 기록 서비스는 DB·네트워크·자격 증명을 분리한다. 상시 실행 작업은 설치하지 않는다.
